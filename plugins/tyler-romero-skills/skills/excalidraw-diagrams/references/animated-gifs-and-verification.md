# Animated Excalidraw GIFs & Visual Verification

## 1. Authoring Animated Excalidraw Frame Sequences

Animated Excalidraw figures (such as parameter-space trajectories, state transitions, or step-by-step algorithm walkthroughs) are generated by writing a sequence of `.excalidraw` files (`frame_000.excalidraw`, `frame_001.excalidraw`, ...) plus a `frames.json` array of per-frame durations in milliseconds.

### Key Rules for Flicker-Free Excalidraw Animations

1. **Lock the canvas bounding box across all frames**:
   `exportToBlob` auto-crops to the bounding box of visible elements. If a moving label or arrow extends near the edge on some frames, the exported PNG dimensions or origin will shift and make the whole animation jitter. Always add a fixed invisible bounding rectangle as the first element of every frame:
   ```python
   s = Scene(seed=391, rough=2)
   s.rect(-110, 0, PANEL_W + 200, PY + PANEL_H + 194, stroke="transparent", roundness=None)
   ```
2. **Keep deterministic seeds and fixed element order**:
   - Initialize `Scene(seed=<fixed_int>, rough=2)` with the **exact same seed** on every frame.
   - Because each element draws its random `seed` and `versionNonce` from `self.rng` in creation order, **always create the exact same sequence of elements in every frame**.
   - To hide an element on certain frames (e.g., force arrows during a sync phase, trail dots not yet reached, or a peak label before the trajectory passes the peak), still call `s.shape(...)` / `s.arrow(...)` / `s.text(...)` in the same order, but pass `opacity=0` (or `opacity=100 if visible else 0`). This guarantees that the hand-drawn wobble of every box, star, and label stays rock-steady from frame to frame.
3. **Smooth motion easing and hold timing**:
   - Interpolate positions between steps using smoothstep easing:
     ```python
     def lerp(a, b, u):
         return (a[0] + (b[0] - a[0]) * u, a[1] + (b[1] - a[1]) * u)

     def ease(u):
         return u * u * (3 - 2 * u)
     ```
   - Use `MF = 3` sub-frames per transition step (`90–110ms` for intermediate frames, `160–320ms` at the end of a step/sync), `900–1000ms` on the initial frame, and `2200–2500ms` on the final frame so the reader can absorb the finished state before the loop restarts.
4. **Suppress per-frame `s.save()` stdout noise**:
   When saving 80+ frames in a loop, pass `quiet=True` to `s.save(path, quiet=True)` and write `frames.json` once at the end:
   ```python
   with open(os.path.join(adir, "frames.json"), "w") as f:
       json.dump(durations_ms, f)
   ```

## 2. Rendering Frames & Assembling the GIF

1. **Batch-render all frames in a single headless browser session**:
   Pass the frame directory directly to [`scripts/render.mjs`](../scripts/render.mjs):
   ```bash
   node "$SKILL_DIR/scripts/render.mjs" /path/to/anim_dir
   ```
   Because `render.mjs` loads `@excalidraw/excalidraw@0.18.1` once and loops over every `frame_NNN.excalidraw` inside the same page context, rendering 80 frames takes only a few seconds.

2. **Assemble and quantize with [`scripts/make_gif.py`](../scripts/make_gif.py)**:
   ```bash
   # Warm cream paper background (default #fef9ed):
   python3 "$SKILL_DIR/scripts/make_gif.py" /path/to/anim_dir path/to/output.gif --bg "#fef9ed"

   # White page / GitHub README background (#ffffff):
   python3 "$SKILL_DIR/scripts/make_gif.py" /path/to/anim_dir path/to/output.gif --bg "#ffffff"

   # Transparent GIF background (1-bit transparency, disposal=2):
   python3 "$SKILL_DIR/scripts/make_gif.py" /path/to/anim_dir path/to/output.gif --bg transparent
   ```
   Why `make_gif.py` is designed the way it is:
   - GIF only supports 1-bit transparency, which causes jagged halos around anti-aliased Virgil text and sketchy strokes. Instead, `make_gif.py` alpha-composites every transparent `frame_NNN.png` directly onto the target page's exact background color (`--bg`, default `#fef9ed`).
   - It computes the union bounding box across all frames (`ImageChops.difference(f, bg).getbbox()`) with `10px` padding so all frames are cropped identically without clipping any frame's extrema.
   - It builds a vertical mosaic of sampled frames (`frames[::max(1, len(frames)//8)] + [frames[-1]]`) so colors that only appear briefly mid-animation are represented during median-cut quantization.
   - It reserves 12 exact RGB palette entries (`fixed`) for the background color and core Excalidraw stroke/fill colors, quantizes the remaining `48 - len(fixed)` colors via `Image.Quantize.MEDIANCUT`, and maps every unique RGB pixel to its **exact Euclidean nearest neighbor** in the 48-color palette. (PIL's built-in `.quantize(palette=...)` uses a coarse 5-bit box lookup that visibly shifts light backgrounds to a different off-white rectangle on the page.)

## 3. Visual Verification Checklist

### Step 1: Alpha Bounding-Box & Margin Check (Static PNGs)
Run this check on every rendered `.png`:

```bash
python3 -c '
from PIL import Image
import sys
for p in sys.argv[1:]:
    im = Image.open(p)
    l, t, r, b = im.getchannel("A").getbbox()
    print(f"{p}: {im.size[0]}x{im.size[1]}  margins L={l} T={t} R={im.size[0]-r} B={im.size[1]-b}")
' path/to/<name>.png
```

- With `exportPadding: 16` and `scale: 1.5`, all four margins (`L`, `T`, `R`, `B`) should be **`24px`** (or balanced within `20–45px`).
- If `R` is much larger than `L` (e.g., `L=24, R=180`), a left-aligned text label has an inflated width or an invisible shape extends to the right. Fix the element before committing.

### Step 2: Direct Image Inspection
View each rendered `.png` (and key frames or contact sheets of `.gif` animations) using the image viewer tool. Check specifically for:
- Text colliding with plotted curves, axes, dotted lines, or arrowheads.
- Multi-line labels overlapping adjacent boxes or legends.
- Clipped descenders or subscripts near the bottom edge.
- Proper typographic minus signs (`−`) and clean alignment of bar labels.

### Step 3: Host Page / Viewport Verification (When Applicable)
When the figure is embedded in a website, blog, or rendered document:
1. Run the project's build/validation command if one exists.
2. Inspect screenshots of the rendered page at **desktop** (`1400×900`) and **mobile** (`375×812`, `deviceScaleFactor: 2`) viewports to confirm that:
   - Desktop view serves the wide layout and mobile view (`375px`) serves any `<name>-mobile.png` layout.
   - Transparent PNGs and background-composited GIFs blend seamlessly into the page background with zero visible bounding-box seams.
   - All figure labels are crisp and readable without horizontal page overflow.
